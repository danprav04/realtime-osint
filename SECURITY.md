# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

We take the security of the Real-Time OSINT Gathering Service seriously. If you discover a security vulnerability, please do **NOT** open a public issue or discussion thread.

### Private Reporting Channels
1. **GitHub Private Vulnerability Reporting**: Use the "Report a vulnerability" button on the repository's Security tab to submit an advisory draft.
2. **Direct Contact**: If GitHub private vulnerability reporting is unavailable, contact the project maintainer directly via GitHub profile contact options.

### What to Include in Your Report
- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions or minimal proof-of-concept (PoC) to reproduce the issue.
- Affected components (e.g. backend authentication, API endpoints, reverse proxy routing, ingestion plugins).
- Any proposed remediations or patches if available.

### Response & Disclosure Process
- **Initial Response**: We aim to acknowledge receipt of reports within 48 hours.
- **Evaluation**: We will investigate the report, verify the issue, and determine its severity.
- **Fix & Disclosure**: We will work on a fix, coordinate disclosure timing, and credit reporters who adhere to responsible disclosure principles.
